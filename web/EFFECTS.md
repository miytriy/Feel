# エフェクト・アニメーションの規約(高画質 × 高フレームレート)

Feel のすべてのエフェクト・アニメーションは、スマホでも60fps以上で、高画質に動くこと。軽いゲームなので、「重いから簡素にする」は理由にしない。重い処理は **事前に画像へ焼き込む** ことで、見た目を落とさずに軽くする。

## 守ること
1. **動かしていいのは `transform`(位置・拡大・回転)と `opacity`(不透明度)だけ。** GPUだけで合成され、再描画も再レイアウトも起きない。
2. **動かしてはいけないもの**(アニメ中に毎フレーム再計算・再描画になる):
   - `filter`(blur / brightness / drop-shadow)のアニメーション
   - `box-shadow` / `background` / `background-position` / `border` の変化
   - `width` / `height` / `top` / `left` / `margin` の変化(→ `transform: translate/scale` にする)
   - SVGフィルター(`feTurbulence`・`feDisplacementMap` など)を、動いている要素にかけること
   - SMIL(`<animate>`)でフィルターの値を毎フレーム変えること
3. **複雑な質感は、事前に画像(WebP・透過)に焼き込む。** 煙・炎・電気・もや・光の揺らぎなど。
   - 解像度は表示サイズの2〜3倍(DPR対応)。
   - 形が変わる動きは、違う模様の画像を数枚重ねて、順にクロスフェード(opacity)+ごくゆっくり漂わせる(transform)。
   - 焼き込みに使うフィルターは、画像を作る時だけ使う(ゲーム実行中には使わない)。
4. 色の見た目をアニメで変えたいときは、変化させたい見た目の層を別に重ねて、その層の opacity を動かす(例: 明るさのフラッシュ = 白い層の opacity)。
5. 動く層には `will-change: transform, opacity` を付ける(常時動くものだけ。付けすぎない)。
6. 画像の置き場所: ゲーム内は `web/public/fx/`、ルール画面の動画は `web/public/rules/`。
7. ルール画面などに載せる動画は、GIFにしない。**60fps・2倍解像度のMP4**(`<video autoplay loop muted playsinline>`)にする。
   - CSSアニメだけの場面は、`document.getAnimations()` で時間を止め、1/60秒ずつ進めて1コマずつスクリーンショット → `ffmpeg -framerate 60` でMP4にする(確実に60fps)。
   - タイマーで動く場面は、CDPスクリーンキャストで撮る(ヘッドレスでは約30fpsが上限なので、その旨を明記する)。

## 例外(許容していること)
- 一度きり(1秒未満)の演出で、フィルターを使うもの(消滅の電気の輪など)は、まだ焼き込んでいない。見直すときは上の方法で画像化する。
- ダメージなどの文字の虹色(`feel-rainbow`)は、`background-position` を動かしている。小さな文字だけなので残している。

## 基準の速さ(エフェクトを作り直すときも、ここを動かさない)
- **消滅**(ルール画面第9章の「消滅」= 戦闘の消滅。**この0.9秒の動きで確定**): 全体 **0.9秒**。段階(全体に対する割合): 青紫の光の円 0〜8%で現れ、22%まで保つ → 電気の輪 3〜10%で現れ、20%まで保ち、20〜30%で小さく縮む → 白い光の核 24〜40% → けむり 26%〜 → 粒と黒いかけら 28〜100%。待ち時間は 950ms。カードは、青い光の円が広がりきる0.07秒までに消える(0.04秒後から0.03秒。11/9に前倒し。それまでは0.07秒後から0.06秒)。もう変えない(「0.9秒のやつはそのままで良い」)。
- 長さは `src/BattleScreen.jsx` の `VANISH_SLOW`(1 = 上の基準)の1か所だけで決まる。戦闘の待ち時間・ルール画面のデモ・各パーツの長さが連動する。再生速度の設定(速い/ふつう/ゆっくり)では変えない(等倍)。
- アルビオンバハムートの消滅も、この同じエフェクトを流す。専用のカットイン(全画面の動画)は、重くて動作が安定しなかったため、11/8 に削除した。
- 数字を変えるときは、変えた理由と日付を、このファイルに残す。

## 消滅の作り直し(11/8): 60fpsの連番画像
- 消滅は、SVGフィルター・ずらしのアニメを全部やめて、**56コマ(0.9秒 = 約62fps)の連番画像**を、1コマずつ見せるだけにした。画像は `public/fx/vanish/sheet.webp`(8列×7行、1コマ400px = 表示の約1.4倍)。
- コマ送りは、1コマ分(約290px)の小さな四角の中で、背景の位置だけを `steps()` でずらす(`src/VanishFx.jsx`: 行 `vx-y` + 列 `vx-x`)。※例外: この1か所だけ `transform` ではなく `background-position`。理由: シート全体(約2300×2000px)を `transform` で動かす作りは、スマホで巨大なレイヤー(3倍の解像度で約7000×6000px)になり、**何も表示されなくなった**(11/8 22:51、実機で「882msで消滅エフェクトが出なくなった」)。小さな四角の背景なら、レイヤーは小さく、再描画も軽い。コマの中身は、上の「消滅」の動き(割合)を、`tools/bake-vanish.cjs` が1コマずつ書き出したもの。動きの元の定義は `tools/vanish-keyframes.css`。
- 作り直す・変えるときは、`tools/bake-vanish.cjs` を実行する(playwright と python3 + PIL が必要)。長さは `VANISH_SLOW`(BattleScreen.jsx)で変えると、同じコマを速く/遅く送る。ライブのSVGフィルターや、CSSで重ねる作りには戻さない。
- 計測(テスト用ブラウザ。倍率3倍): 5体同時でも約61コマ/秒(最大の止まり17ms。作り直す前は約19コマ/秒、最大190ms)。1回の再生は約896ms、見えたコマは57種。
- 端末で実際に何msかかったかは、テスト戦の画面の上に「消滅 ◯◯◯ms」と出る。

## 消滅の表示を canvas に変更(11/9)
- 症状: ときどき「めっちゃ速く再生される」「途切れる」(PC)。推測の原因: 約3200×2800pxの画像のデコードで画面が固まり、その間も時計だけ進む/背景位置のアニメで再描画が走る。
- 対応: `src/VanishFx.jsx` を `<canvas>` に変更。起動時に1回だけ画像をデコード(ImageBitmap)して全員で使い回し、1コマ(400px)だけを `drawImage` で描く。時計は経過時間(rAF)で決めるが、**コマは飛ばさない**(11/9: 「重いとき飛ぶのが気になる」。1回の描き換えで最大1コマ。重いときは、終わりが0.9秒より遅れる)。読み込みが終わるまで時計を始めない。`vx-x`/`vx-y` のキーフレームは削除。
- 見た目・長さ(0.9秒、56コマ)・画像は変えていない。実機での確認はこれから。計測: テスト戦の「消滅 ◯◯◯ms」。

## 進化の作り直し(11/9): 参考動画の再現(ユニットは回転させない)

- 質感は `web/tools/bake-evolve.py` で `web/public/fx/evolve/{rays,rainbow,chain}.webp`(1024px・透過)に焼き込み。ゲーム中に動かすのは transform と opacity だけ。変えるときは、このスクリプトを実行する。
- 参考動画のユニットの「ひっくり返る」動きは、入れていない(依頼どおり)。
- 確認: 参考動画と同じ時刻の12コマを並べて、段階が一致することを見た。5体同時・実機での滑らかさは未確認。

## ランダムマッチ画面の動き(11/10)
- `src/RandomMatchScreen.jsx` の動きは、すべて `transform` と `opacity` だけ。背景(ゆれる光の筋・ゆっくり漂う光の玉・上へ昇る光の粒16個、スマホは8個)、入場(ルール・デッキを順番にすべり込ませる、タイトルの線が伸びる、バッジがはずんで現れる、BPバーが伸びる、BPの数字を数え上げる)、バッジ(浮遊・斜めの光・きらめき)、バトルボタン(呼吸・二重の波紋・光・回る点線の輪2本)、検索中(レーダーの回る光・点滅する点・周回する光・跳ねる「…」・秒ごとの数字の弾み)。
- 画像の焼き込みは使っていない(グラデーションの層を、transform で動かすだけ)。数字の数え上げだけ、JSで文字を更新している(レイアウトは動かない)。
- 確認: テスト用ブラウザで表示と、エラーが出ないことを見た。実機のフレームレートは未確認。ランクマッチ(ログイン中)のバッジの動きは、ログインが必要で、画面では確認できていない。

## ルール画面の見た目と動き(11/10)
- `src/RulesScreen.jsx`: 見出しのバナー(ゆれる光の筋・昇る光の粒)、読んだ量のバー、章ごとに色を変えた見出し(六角のバッジ・伸びる線)、用語のタグ表示、画面に入ると現れる章、押すと浮く目次、「上へ」ボタン、呼吸する「あそびはじめる」ボタン。
- 動くのは `transform` と `opacity` だけ。読んだ量のバーは、スクロールを rAF で間引いて `scaleX` だけ更新している。画像の焼き込みは使っていない。文章の中身は変えていない。
- 確認: テスト用ブラウザで、スマホ幅・PC幅の表示とエラーなしを見た。実機のなめらかさは未確認。

## 名前のスクロール(11/12)
- 戦闘中のユニットカードの名前が枠に入り切らないときは、2行にせず、電光掲示板のように左へ流れ続ける(`NameMarquee`、`feel-marq`)。transform だけで動かす。速さは 34px/秒、1周の空きは 28px。
